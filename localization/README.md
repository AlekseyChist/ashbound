# Каталоги AshBound — LOC-01A

Два основных языка: `en` и `ru`. PO-каталоги используют устойчивые ключи; `messages.pot` содержит тот же набор с пустыми переводами. Девять стартовых сообщений — техническая основа интерфейса, не перевод всего двора или сюжета. Пояснения для переводчика находятся перед сообщениями. Тексты обоих языков добавляются вместе.

`Localization` загружается перед игровыми системами. `load_preferences()` читает `user://settings.cfg`, раздел `localization`, ключ `language`: `auto`, `en` или `ru`. Русское семейство локалей устройства выбирает русский, остальные неподдерживаемые языки — английский. Явный выбор приоритетнее устройства. Другие секции настроек сохраняются. Кампанийный файл и ID предметов/квестов от языка не зависят.

- `set_language("ru")` возвращает `Error`: только успешная запись меняет активный выбор. Будущее меню обязано обработать ошибку сохранения настройки.
- `get_language()` возвращает применённый язык, `get_preference()` — выбор, включая `auto`.
- `language_changed(language)` отправляется при изменении применённого языка. Динамические подписи должны обновлять отображение, не выполнять игровые действия заново.
- `text("UI_GREETING", {"name": name})` переводит целое предложение и подставляет параметры за один проход. Содержимое пользовательского имени повторно не форматируется.
- `text_plural("UI_ITEM_COUNT", "UI_ITEM_COUNTS", count)` использует формы PO; аргумент `count` имеет приоритет над одноимённым параметром словаря.

В обычных Godot-элементах доступны также стандартные `tr()`/`tr_n()`. Для динамической подписи нужно хранить ключ и исходные параметры, а не только уже переведённый текст. Пропущенные переводы получают английский резерв; неизвестный ключ/непереданный параметр остаётся заметен при QA и не считается готовым контентом.

Реестр первых ключей: `UI_LANGUAGE`, `UI_LANGUAGE_AUTO`, `UI_CLOSE`, `UI_ACTION_INTERACT`, `UI_ACTION_ATTACK`, `UI_ACTION_RUN`, `UI_ACTION_WALK`, `UI_GREETING`, `UI_ITEM_COUNT` (множественный ключ `UI_ITEM_COUNTS`). При расширении обновлять каталоги, шаблон и реестр в `tools/validate-localization-catalogs.mjs`. Переводы не должны включать команды или менять условия квестов.

Проверка каталога: `node tools/validate-localization-catalogs.mjs`. Проверки поведения описаны в [протоколе](../docs/production/LOCALIZATION_FOUNDATION_CHECKS.md). Каталоги `.po` должны попадать в оба ограниченных пресета экспорта; одного наличия строк в исходниках недостаточно.

Формат и импорт основаны на [gettext в Godot](https://docs.godotengine.org/en/stable/tutorials/i18n/localization_using_gettext.html) и [TranslationServer](https://docs.godotengine.org/en/stable/classes/class_translationserver.html). Настоящий выбор языка в интерфейсе, перенос двора, визуальная проверка макетов и телефонный сценарий остаются LOC-01B/LOC-02.
