# База путешественника и рабочие слои экипировки

ART-BASE-01, 22 сентября 2026. После исправления рюкзака владелец предложил строить внешность от общей базы и поручил продолжить этот подход. Здесь зафиксирован первый рабочий набор: **84 существующие позы путешественника** и редактируемые слои рюкзака. Каждый результат для игры остаётся цельным PNG.

[Лист сравнения](reference-sheet.png): в каждой тройке слева база, в центре цветовой слой правок рюкзака, справа готовая фигура. Показаны пять действий и три нарисованных ракурса; безоружный левый бок по прежнему правилу зеркалируется в игре.

## Состав

| Источник | Назначение |
| --- | --- |
| [manifest.json](manifest.json) | Версия базы, SHA-256 семи исходных PNG и двух SpriteFrames, 84 прямоугольника с опорными полями, имена слоёв и результатов |
| `assets/characters/courtyard/traveler*.png`, перечисленные в manifest | Неизменяемая база: лицо, тело, базовый комплект и готовые позы. Вторые копии этих файлов не создаются |
| `layers/*-backpack.png` | Цветовые правки экипировки: рюкзак, ремни, контактные тени и складки для соответствующих поз |
| `layers/*-mask.png` | Чёрно-белая маска: белый пиксель заменяет RGBA базы пикселем из слоя; чёрный сохраняет базу |
| [capture_sources.py](capture_sources.py) | Воспроизводимый первоначальный перенос опубликованных рисунков 0.15.2 в рабочие слои; пишет отдельный новый каталог `.tools/character-base-capture` |
| [build_character_base_layers.gd](../../../scripts/tools/build_character_base_layers.gd) | Сборщик локальной Ollama: проверяет неизменность базы и собирает семь цельных атласов только в `.tools/` |
| [validate_character_base.py](../../../tools/validate_character_base.py) | Независимые проверки Codex: совпадение выпущенных кадров, пробная правка экипировки и повреждённые входные данные |

Исходники выделены из уже выпущенных пар, а не нарисованы заново. `capture_sources.py` отказывается перезаписывать существующий каталог; рабочие слои рядом с этим README он не изменяет. Повторное извлечение после начала ручной работы не используется вместо сохранения правок художника.

## Как готовить следующий вариант

1. Открыть соответствующий базовый PNG как неподвижный образец. Сохранить его размер 1254×1254, координаты и фазы поз. Положение каждого кадра задано в manifest; соседние контрольные рисунки исходного листа не входят в выпуск.
2. Редактировать отдельный цветовой слой экипировки. Ремни, наклон рюкзака, тени и перекрытие руками готовятся для каждой позы. Белая область маски определяет, какие пиксели переносятся в итог; растушёвка цвета и частичная прозрачность хранятся в самом цветном слое, маска остаётся строго 0/255.
3. Собрать цельные PNG в `.tools/character-base/export`. Проверить полный кадр, анимацию, лицо, опору и пары с экипировкой/без. Сборщик не меняет `assets/`, импорт, SpriteFrames или открытую игру.
4. После проверки переносить утверждённый вариант отдельной задачей: игровые ресурсы подключает Ollama, Codex проверяет Godot, Windows/Android и фактическую экипировку. Масштаб тела и длительности берутся из общей базы.

Замена RGBA нужна для точного сохранения полупрозрачных краёв: обычное наложение полупрозрачного слоя поверх уже существующего края меняет его цвет и плотность. Это формат рабочих правок, не игровой эффект и не отдельный Sprite3D аксессуара. Для просмотра отдельный слой может выглядеть фрагментарным — оценивать нужно собранную фигуру.

Сборщик проверяет хэши базы и исходных SpriteFrames. PNG проверяются побайтно; у двух текстовых SpriteFrames перед хэшированием CRLF приводится к LF, чтобы обычный Git checkout Windows не считался изменением позы. Для рюкзака запрещены правки верхней части головы и нижней части тела внутри каждого базового прямоугольника. Новая одежда и оружие потребуют собственных согласованных зон правки; нельзя молча ослаблять ограничения рюкзака. Проверки силуэта, перекрытий и художественная оценка также остаются обязательными.

## Запуск

Из корня репозитория, установленным Godot из `GODOT_CONNECTION.md`:

```powershell
& .tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://scripts/tools/build_character_base_layers.gd
python tools/validate_character_base.py
```

Проверке Python нужны Pillow и numpy. У сборщика нет зависимости от Python или импортированных текстур. Для отдельной проверки допускаются `-- --manifest res://... --output-dir res://.tools/...`; запись в игровые каталоги запрещена. Успех — `ASHBOUND_CHARACTER_BASE_BUILD_OK sheets=7 poses=84`, код 0 и отсутствие ошибок движка.

## Границы первой базы

Это существующий путешественник **в базовой одежде**, а не универсальный анатомический манекен и не 3D-риг. В набор входят покой, ходьба, бег, прежний удар и жест кармана. Двенадцать новых фаз удара новичка из отдельной пробы 0.15.0 пока остаются своим арт-набором. Новое движение сначала получает согласованные базовые позы, затем варианты снаряжения.

Эта задача подготавливает исходники и не выпускает новую одежду, оружие, анимацию или механику. Игра сохраняет версию 0.15.2. [Цельные варианты](../../../docs/art/CHARACTER_VARIANTS.md), [предыдущая правка пропорций](../../../docs/production/BACKPACK_PROPORTIONS_CHECKS.md).

[Приёмка процесса](../../../docs/production/CHARACTER_BASE_WORKFLOW_CHECKS.md): 20 запусков Godot, семь атласов / 11 007 612 точных RGBA-пикселей, 17 отказов с сохранением прошлых результатов, CRLF и допустимая отдельная правка экипировки. Игровые исходники и установленные сборки не изменены.
