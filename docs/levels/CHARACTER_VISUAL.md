# Компонент внешнего вида героя

Техническая основа VIS-01: ракурс, анимация и масштаб 2D-рисунка отделены от движения и боевых таймеров. По D-079 от 24 сентября CHAR-01 исключена; герой имеет одну принятую внешность. API замены совместимых наборов кадров сохраняется для цельной экипировки/действий. Название appearance в существующем API не означает редактор лица или волос; сами API и игровые данные в этом решении не меняются.

`scripts/courtyard/courtyard_character_visual.gd` установлен на узле `Visual` сцены героя. Существующие пути `Visual/Body` и `Visual/Equipment` сохранены. Игрок выбирает действие, направление движения и частоту поз; компонент выбирает соответствующие кадры относительно камеры. Скорость, столкновения, ввод и момент нанесения удара остаются в контроллере игрока.

## Контракт

- `update_visual(action, facing_direction, walk_pose_fps)` обновляет изображение. Смена действия запускает его анимацию; смена только ракурса сохраняет фазу и состояние паузы.
- `get_visual_direction()` возвращает текущий ракурс; прежний метод игрока сохраняется и перенаправляет вызов.
- `set_appearance_frames(frames)` меняет совместимый `SpriteFrames`, сохраняя действие, ракурс, фазу и состояние проигрывания. При меньшем количестве кадров индекс ограничивается доступным диапазоном. Замена не перезапускает атаку и не испускает событие попадания.
- Ресурс должен иметь непустые `idle`, `walk`, `attack` для `back`, `front`, `side`, с текстурами и положительной частотой. Неполный ресурс отклоняется целиком. Инициализация внешности допустима до первого обновления анимации.
- Масштаб и опорная линия берутся из метаданных набора, как и до выделения компонента. Общие ресурсы не изменяются; внешний вид одного экземпляра не меняет остальных.

Это API замены полного совместимого набора. Послойная одежда/волосы, разные хваты оружия и выбор внешности в интерфейсе будут следующими отдельными задачами. Набор проверочных копий в тесте не считается готовым игровым костюмом.

## Приёмка

Отдельный сценарий `scripts/tools/validate_character_visual.gd` проверяет отклонение плохого ресурса без изменений, сохранение фазы/паузы, смену во время удара, масштаб ракурсов, независимость экземпляров и начальную установку внешности. Проверена также установка набора до входа в дерево без старых алиасов: Godot сбрасывает прежний `autoplay`, поэтому компонент переносит непустой автозапуск на выбранный направленный клип. Пустой автозапуск не включается принудительно.

Семь сценариев Godot и запуск отдельной Windows-сборки прошли. Android 0.3.1 установлен и запущен на OnePlus; после разблокировки владельцем на экране зафиксирован завершённый учебный маршрут. [Фактический протокол](../production/CHARACTER_VISUAL_CHECKS.md).
