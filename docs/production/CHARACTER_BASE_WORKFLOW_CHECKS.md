# Общая база и слои экипировки — ART-BASE-01

22 сентября 2026. Продолжение идеи владельца после 0.15.2: фиксировать базового персонажа и дорисовывать экипировку в рабочих слоях, затем выпускать цельные кадры. Ветка `codex/character-base-sources` от `dev` `7bc4e61` после PR #41. Игровая версия остаётся **0.15.2-backpack-proportions**.

## Объём

[Исходный набор](../../art/characters/traveler-base-v1/README.md) фиксирует семь существующих PNG и два SpriteFrames путешественника: 84 уникальные позы покоя, ходьбы, бега, прежнего удара и жеста кармана. Для каждой позы сохранены прямоугольник и исходные поля `margin`, включая дробные координаты. Хэши текстовых ресурсов вычисляются после приведения CRLF к LF; PNG проверяются побайтно.

Подготовлены семь цветовых слоёв рюкзака и семь бинарных масок. Маска задаёт точную замену RGBA, сохраняя полупрозрачные края. В слои входят ремни, контактные тени, складки и нужные перекрытия. Это производные уже выпущенных кадров 0.15.2; новой генерации тела не было. При извлечении изменяемая область составила 309 381 пиксель; все семь полных атласов воспроизводятся точно.

`capture_sources.py` — подготовка арт-исходников Codex по разрешению владельца на программную обработку PNG. `build_character_base_layers.gd` — сборщик локальной Ollama. Он читает замороженную базу и рабочие слои, проверяет входные данные, собирает все изображения в памяти и только после проверки пишет цельные PNG в `.tools/`. Игровые атласы, SpriteFrames, масштабы и фазы не перезаписываются.

База сейчас содержит существующий обычный комплект одежды. Смена всего комплекта, новое оружие, анатомический манекен и новые базовые движения являются отдельными художественными задачами. Двенадцать новых фаз новичка из 0.15.0 пока остаются отдельным набором. Процесс не возвращает отвергнутый отдельный Sprite3D аксессуара.

Полный QA завершил **20 запусков Godot**: базовая сборка, CRLF, 17 отказов и разрешённая правка. Исходники во всём рабочем проекте изолированы от повреждённых фикстур; контрольные суммы всех входных файлов после QA совпали с исходными. Результаты — `.tools/character-base-qa/*.log`, собранные образцы — `.tools/character-base-qa/export/`, дополнительный запуск — `.tools/character-base-root-build.log` и `.tools/character-base/export/`.

Повторное извлечение слоёв в новый каталог воспроизвело manifest и 14 PNG побайтно. Проверены 231 локальная ссылка документации, `git diff --check`, неизменность игровых ресурсов/версии относительно `7bc4e61`, хэши четырёх прежних пакетов и шести пользовательских `.import`.

Первая реализация Ollama была отклонена: ошибки API `Image.load`/`set_data`, передача строковых параметров по значению, неверный запрет дробных `margin`, обрезка рюкзака прямоугольником тела и слишком поздняя проверка имён. Модель исправила их, затем исправила неверный вызов SHA-256; Codex не подменял игровую реализацию. Промежуточные ответы и завершения по лимиту ходов не считались приёмкой. Фактические журналы Ollama: `.tools/ollama-godot/runs/2026-09-22T09-08-07-598Z`, `09-21-03-085Z`, `09-25-53-583Z`, `09-33-46-008Z`.

## Воспроизведение

```powershell
& .tools/godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --script res://scripts/tools/build_character_base_layers.gd
python tools/validate_character_base.py
```

Python требует Pillow и numpy. QA создаёт отдельный временный проект под `.tools/`, вызывает настоящий Godot, сравнивает результат с опубликованными PNG и вводит повреждения только в копии. Принятый результат требует завершения сценариев, ожидаемых кодов выхода и отсутствия `SCRIPT ERROR` / ошибок движка.

## Границы

Эта задача меняет процесс подготовки арта и добавляет инструменты, не меняя игровую сборку. Пакеты Windows/Android 0.15.2 не пересобираются и не переустанавливаются, открытая владельцу проба не прерывается. Ранее выполненные проверки S23 относятся к 0.15.2; новый мобильный прогон этой задачи не заявляется. OnePlus и личная художественная приёмка остаются открытыми.

Следующая игровая задача — входящая атака и доступная защита COMBAT-01/02; подготовленная база используется при создании следующих поз и вариантов. Исходные шесть пользовательских `.import` сохраняются вне коммита, `main` не обновляется.
