# RUN-01 — протокол проверки

20 сентября 2026. Ветка `codex/courtyard-running`, основа `dev` после PR #6 (`d18ebe6`). Игровой код, ресурсы, сборщик кадров и сценарии проверки написаны локальной `qwen3.8-24k:latest` через Ollama; Codex проверил изменения и запустил Godot. PNG созданы встроенным image_gen. Логи модели и проверок лежат в игнорируемой `.tools/`.

Опубликован [черновик PR #7](https://github.com/AlekseyChist/ashbound/pull/7) в `dev`. На момент открытия конфликтов нет, GitHub CI не настроен. Первоначально слияние ожидало повторной проверки на устройстве; актуальный отзыв указан ниже.

**Статус: технические проверки пройдены; после запуска 0.4.1 на S23 получен положительный отзыв владельца.** Владелец сообщил, что ему нравится внешний вид и ощущение игры на телефоне; единственное замечание — приблизить камеру. Это позволяет завершить RUN-01 и сделать камеру отдельной веткой. Предыдущее замечание относилось к 0.4.0, а новая 0.4.1 уже установлена на S23; [подтверждение запуска](DEVICE_SMOKE_CHECKS.md).

## Проверки в Godot 4.7.2

Во всех перечисленных успешных запусках проверены завершающий маркер и отсутствие `ERROR` / `SCRIPT ERROR`, а не только код выхода.

| Сценарий в `scripts/tools/` | Проверено | Результат |
| --- | --- | --- |
| `validate_courtyard.gd` | Учебный маршрут, порядок действий, повторный старт | `ASHBOUND_COURTYARD_OK` |
| `validate_third_person.gd` | Камера и ракурсы героя | `ASHBOUND_THIRD_PERSON_OK` |
| `validate_character_visual.gd` | Смена совместимой внешности, фазы и отсутствие изменения механики | `ASHBOUND_CHARACTER_VISUAL_OK`; повторён с атласами v3 |
| `validate_target_feedback.gd` | Выбор и подсветка цели | `ASHBOUND_TARGET_FEEDBACK_OK` |
| `validate_camera_touch.gd` | Сенсорный обзор и владение касанием | `ASHBOUND_CAMERA_TOUCH_OK` |
| `validate_courtyard_touch.gd` | Сенсорное управление двора | `ASHBOUND_COURTYARD_TOUCH_OK` |
| `validate_target_input.gd` | Свободное касание, эмуляция мыши, намеренный удар | `ASHBOUND_TARGET_INPUT_OK`; оконный запуск |
| `validate_courtyard_run.gd` | Скорость, диагональ, Shift, атака из бега, остановка, стена, ракурсы, старые наборы кадров | `ASHBOUND_COURTYARD_RUN_OK`; повторён после последней калибровки v3 |
| `validate_courtyard_run_touch.gd` | Переключатель бега, движение/обзор/удар, эмуляция мыши, отпускание, сброс и потеря фокуса | `ASHBOUND_COURTYARD_RUN_TOUCH_OK` |

Измерено: ходьба 4.2000 м/с, бег и диагональный бег 6.4000 м/с. Дистанция в одинаковом сценарии при 15 и 5 позах/с — 5.4289 м в обоих случаях. Атака из бега порождает одно попадание; счётчик physics frames показывает 0.116667 с (событие проверяется с дискретностью 1/60 с), скорость в активной атаке после торможения — 1.0500 м/с. Длительность и таймеры атаки не менялись.

Механический тест запускается с `--headless --fixed-fps 60 --quit-after 1500`. Сенсорные тесты с защитой от эмулированной мыши запускать **без `--fixed-fps`**: защита использует реальные миллисекунды. `validate_target_input.gd` запускать с оконным рендерером. Все сценарии — через `--path . --script scripts/tools/<имя>.gd`.

## Сравнение рисунков

Новые исходники: `assets/characters/courtyard/traveler-run-side-v3.png`, `traveler-run-front-v3.png`, `traveler-run-back-v3.png`, по 1254×1254 с альфой. В игре используются верхние восемь кадров каждого атласа. Исходные idle/walk/attack сохранены. [Полные промпты](../../art/concepts/first-courtyard/RUN_REDRAW_PROMPTS.md).

Ollama обновила `build_courtyard_run_frames.gd`. Масштаб бега для каждого ракурса равен 0.90 от исходного `pixel_size` этого ракурса. Калибровка выполнена визуально по голове/корпусу, без увеличения согнутой позы до стоячей высоты. Все кадры имеют общий виртуальный холст и линию опоры. Это ещё прототип рисованного цикла, не утверждённая финальная анимация.

`capture_run_comparison.gd` использует двух одинаковых игроков, одну камеру, одинаковое расстояние и штатные параметры ресурсов, затем останавливает оба клипа на выбранном кадре. Сняты и просмотрены кадр 3 в трёх ракурсах и дополнительно боковой кадр 0. Ошибок рендера/пустых текстур нет. На сравнении исчезло прежнее заметное увеличение головы и корпуса при беге; восприятие перехода в движении должен повторно оценить владелец.

- Профиль: ходьба слева, бег справа.
- Спереди.
- Со спины.

Воспроизведение: оконный запуск `capture_run_comparison.gd` с аргументами после `--`: `--output=<абсолютный путь PNG> --view=side --frame=3 --no-mouse-capture`. Аналогично `front` и `back`.

## Оставшаяся приёмка

После установки 0.4.1 на S23 владелец положительно оценил изображение и ощущение игры, попросив только приблизить камеру. Ожидание художественной оценки текущего варианта закрыто этим отзывом; изменение камеры выполняется отдельно, без перерисовки героя. Новый APK на OnePlus пока не устанавливался.

Полный сценарий на Samsung S23, длительный тепловой тест, окончательный баланс скорости и выносливость этой проверкой не закрыты.

После обновления ветки до dev с PR #9/#10 повторены validate_inventory_transactions, validate_inventory_events, validate_courtyard_run и validate_courtyard_run_touch: все четыре завершились соответствующими ASHBOUND_*_OK без ошибок скриптов. Конфликт оглавления docs/README.md разрешён сохранением всех ссылок; игровой код при разрешении конфликта не менялся.
