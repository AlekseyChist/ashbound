# TECH-01 — снимок и проверяемая загрузка Inventory

20 сентября 2026. Фича `codex/inventory-snapshot-validation` от `dev` (`e848f9e`, слияние [PR #16](https://github.com/AlekseyChist/ashbound/pull/16)). Реализация игрового API — локальная Ollama, тесты и проверка — Codex.

## Область и контракт

Это подготовка данных инвентаря к сохранению, **не полная система сохранения кампании**. Прежний `get_save_data` возвращал живые массивы/словари: правка снимка меняла вещи героя и наоборот. `load_save_data` принимал состояние без проверки и сохранял ссылки на входные данные.

Новый контракт:

- Снимок содержит `schema_version: 1`, `items`, `equipped`, `gold`. Коллекции и вложенные характеристики/эффекты копируются глубоко. Снятие снимка не уведомляет и не меняет игру.
- Загрузка возвращает `bool`. До изменения игры проверяются обязательные поля, типы, версия, баланс, вместимость, известные ID предметов, уникальные `instance_id` во всех местах, количество/стопки, допустимые слоты и числовые характеристики/эффекты. Непригодное состояние отвергается целиком, без частичной загрузки, сигналов и изменения прежних ссылок.
- При успехе принимается отдельная копия, характеристики пересчитываются после замены состояния. `inventory_restored` и `gold_changed` сообщают уже готовое состояние; события получения/использования/экипировки каждого предмета заново не проигрываются. Повторная загрузка или денежная операция из этих уведомлений блокируется. Во время уведомлений торговли загрузка также не может заменить весь инвентарь.
- Значения конкретного улучшенного экземпляра сохраняются, а не сбрасываются к каталогу; каталог задаёт структуру типа/стопки/слота. Метаданные поддерживают обычные вложенные данные; ссылки на объекты/вызовы и недопустимая глубина отвергаются.

Формат этого API — **типизированные данные Godot**, проверенные через `var_to_bytes` / `bytes_to_var` без объектов. Он сохраняет целые int64, включая максимальный баланс, без преобразования через float. JSON-словарь не подаётся в этот API с неявным округлением чисел. Текущий старый JSON-файл GameManager не содержит Inventory; его замена, файловый формат, резервная запись, загрузка игрока/квеста и миграция выполняются отдельно в SAVE-01. Наличие API снимка не означает, что выход из текущего двора уже сохраняет вещи на диск.

Версия без `schema_version` и неизвестная версия отклоняются. Раньше кампанийный инвентарь на диск не записывался; автоматическая миграция несуществующей схемы не добавляется. Локализация будущего меню использует ID/данные, а не меняет сохранённые экземпляры из-за языка.

## Проверки Codex

Основной `scripts/tools/validate_inventory_snapshot.gd` содержит восемь групп: изоляция снимка, изоляция загрузки и характеристики, неверная структура, предметы, экипировка, типизированный круговой перевод данных, повторный вход при загрузке и попытка загрузки во время торговли. Каждая группа обязана завершиться; проверяются также уведомления и сохранение входных данных при отказе.

На исходном `dev` контрольный тест завершил восемь групп и выявил **105 нарушенных утверждений**. SHA-256: `E698B6482245AC9EAF478AE65D0C4E3BB3553D0F3498B947658D3301880795D5`. Число относится к проверкам контракта, не к количеству независимых дефектов.

Дополнительный `scripts/tools/validate_inventory_snapshot_edges.gd` содержит шесть групп: неправильные контейнеры, значения/слоты, глубокая изоляция обычных метаданных, недопустимые объекты/циклы/глубина, пустой корректный инвентарь и границы вместимости/обязательные поля. Надетые вещи не занимают места в сумке; съедобный предмет нельзя надеть, добавив ему поле слота. Изменяемые ключи метаданных отвергаются, чтобы не сохранить внешнюю ссылку.

Первый результат Ollama отклонён: ошибка синтаксиса в проверке `null` не позволила загрузить Inventory; чтением также найдены пропущенные проверки назначения слота и сохранённого ограничения стопки. Остановлены только два созданных для этого неуспешных headless-процесса. При следующих запусках добавлен предел кадров и обязательная проверка маркера завершения вместе с журналом; сам выход 0 не подтверждает результат.

Чтение уже проходившей первые проверки реализации выявило дополнительные дефекты: экипировка учитывалась в вместимости сумки, отсутствующие поля получали значения по умолчанию, пищу можно было загрузить в слот оружия, изменяемый ключ метаданных сохранял ссылку. Новая шестая группа воспроизвела 15 нарушенных утверждений. Ollama исправила игровые методы; Codex повторно прочитал изменения и выполнил проверки.

Финальный результат на Godot 4.7.2: восемь основных и шесть дополнительных групп завершились успешно, без ошибок скриптов/движка. SHA-256 основного контрольного файла совпал с исходным выше. Шесть прежних проверок Inventory также прошли, включая 600 торговых операций; учебный маршрут двора и импорт редактором прошли. Остались прежние предупреждения старой сцены о UID FBX и объёмном тумане вне Forward+.

Журналы: `.tools/validate_inventory_snapshot-final.log`, `.tools/validate_inventory_snapshot_edges-final.log`, `.tools/snapshot-regression-*.log`, `.tools/snapshot-editor-import.log`. Каждая проверка проверена по коду выхода, обязательному маркеру завершения и отсутствию ошибок, а не только по сообщению исполнителя. Нового APK или интерфейса сохранения эта задача не добавляет; устройство этим API-проходом не проверено.

## Воспроизведение и границы

Из корня проекта, установленный Godot 4.7.2:

```text
godot --headless --path . --quit-after 120 --script scripts/tools/validate_inventory_snapshot.gd
godot --headless --path . --quit-after 120 --script scripts/tools/validate_inventory_snapshot_edges.gd
```

Оба теста синхронные и завершаются раньше предела кадров; предел останавливает процесс при неработающем autoload. Нужны ожидаемые `ASHBOUND_INVENTORY_SNAPSHOT_OK groups=8` / `ASHBOUND_INVENTORY_SNAPSHOT_EDGES_OK groups=6` и отсутствие ошибок. Проверки не пишут пользовательские сохранения. Журналы `.tools/*snapshot*.log` и авторство `.tools/ollama-godot/runs/` остаются локальными.

Следующий видимый этап — LOC-01/02 перед меню; файловая интеграция SAVE-01 должна отдельно связать вещи с прогрессом двора, местоположением и заданиями. Правила полного сохранения, восстановления прерванной записи и проверки Android не объявляются готовыми этим тестом.
