# TECH-01 — деньги и торговые операции

20 сентября 2026. Фича `codex/inventory-trade-transactions` от `dev` (`fe4a8ac`). Игровой код — установленная локальная Ollama; оба теста и независимая проверка — Codex. Область: общие операции Inventory, до подключения меню и полноценной торговли с NPC.

## Проверяемый контракт

- Баланс неотрицательный, в диапазоне целого int64. Начисление/списание принимают положительную сумму; нулевой или отрицательный платёж, недостаток и переполнение не меняют состояние и не уведомляют. Проверка доступности нулевой суммы допустима при корректном балансе.
- Покупка добавляет одну единицу по положительной цене. Сначала проверяются деньги и место; полный список допускает пополнение имеющегося стека. Бесплатная выдача остаётся отдельной операцией добавления предмета. Неверный ID отклоняется штатно.
- Продажа принимает ссылку по `instance_id`, остальные поля аргумента не определяют сделку. Цена, ID и количество берутся из единственной принадлежащей герою записи в сумке. Из выбранного стека уходит одна единица; надетый, отсутствующий, проданный или неоднозначный экземпляр не продаётся. Подделанная цена в копии не увеличивает выручку.
- Предметы и деньги обновляются до первого уведомления о сделке. Сигнал добавления указывает на настоящую изменённую запись; продажа сообщает настоящий ID. По одному событию предмета и баланса; отказ без событий. Во время уведомлений о торговле повторный вызов торговых/денежных операций отклоняется, следующая явная сделка после возврата допустима.

## Независимые проверки

`scripts/tools/validate_inventory_trade.gd`: 14 групп — суммы/нулевые операции, int64, ошибки покупки, покупка на весь баланс, полный список и стек, чужая/поддельная ссылка, цена настоящей вещи, конкретный стек, проданная/надетая вещь, дубли ID, неправильное количество/цена, переполнение продажи, повторные вызовы из событий покупки и продажи. Счётчик завершённых групп не позволяет пропуску функции при ошибке скрипта выдать успех.

Контрольный запуск на исходном коде: выход 1, завершены 14 групп, нарушены **83 проверки**. Это число невыполненных утверждений, не 83 независимых дефекта. Журнал также содержит ошибку движка для неизвестного ID покупки. SHA-256 основного теста: `A55639969D18F61A3B7F0D6CA01B718B0956531333D46A3F492A104A1873BFE7`.

`scripts/tools/validate_inventory_trade_edges.gd`: восемь групп — типы некорректных данных, невалидный баланс, конфликт экземпляра с экипировкой, повторный вызов из уведомления баланса, максимальная цена, правильная ссылка события при двух стеках и 600 сделок с проверкой сохранения общей стоимости. Сумма золота и стоимости предметов остаётся постоянной; дополнительно проверяются вместимость, уникальные ID и итоговое состояние во всех уведомлениях.

Первую реализацию отклонили: оставались повторный вход, неверная ссылка в событии пополнения стека, конфликт с копией надетой вещи и пропуск невалидного количества. Второй запуск модели исчерпал попытки на некорректном диапазоне чтения; для следующего задания передан точный фрагмент исходника. Ответ модели не считается результатом проверки.

Финальная проверка после исправлений:

- Основной тест — выход 0, `ASHBOUND_INVENTORY_TRADE_OK groups=14`, без ошибок движка. Хэш основного теста совпадает с контрольным красным запуском: ожидаемое поведение не ослаблялось.
- Граничный тест — выход 0, `ASHBOUND_INVENTORY_TRADE_EDGES_OK groups=8 exchanges=600`, без ошибок движка; все группы завершены, общая стоимость сохраняется во всей последовательности.
- Прежние `validate_inventory_transactions`, `validate_inventory_events`, `validate_inventory_ownership` и `validate_inventory_ownership_edges` — выход 0 и их маркеры успеха, без ошибок в журналах.
- `validate_courtyard` — выход 0, `ASHBOUND_COURTYARD_OK`: учебный маршрут, три попадания и одинаковое расстояние 3,793 м при 5/15 позах в секунду.
- Импорт редактора — выход 0, без `SCRIPT ERROR`/`ERROR`. Остались прежние предупреждения старой сцены о UID FBX и объёмном тумане вне Forward+; эти ресурсы не менялись.

Все автоматические проверки выполнены Codex на Windows, Godot 4.7.2. Android-экспорт и новый магазин на устройстве в эту задачу не входят: двор ещё не подключён к общему торговому API. Следом — независимый снимок/валидируемая загрузка Inventory, затем LOC-01/02 перед новым меню. Правка подготовлена для отдельного PR в `dev`; фактическое слияние фиксируется GitHub/историей Git.

По постоянной просьбе владельца открыт отдельный видимый `ASHBOUND (DEBUG)` для ручного теста ПК; получен `ASHBOUND_COURTYARD_READY` без ошибки запуска. Управление: WASD, мышь для обзора, Shift для бега, E для действия, ЛКМ для удара, Esc для курсора. Редактор с несохранённой сценой не закрывался. Запуск окна не подменяет личную приёмку и не показывает ещё не подключённый магазин.

## Границы

`buy_item(id, price)` остаётся внутренней операцией с доверенной ценой вызывающего слоя. Проверенные платежи сами по себе не создают котировки торговца, запас товара, наценки, договоры или защиту публичных массивов от прямой записи другого игрового кода. Эти вопросы относятся к интеграции торговли и валидации сохранений. Снимок/загрузка Inventory и полноценная запись кампании — следующие самостоятельные задачи.

Текущий учебный двор не вызывает эти торговые методы. Его запуск проверяет совместимость общих изменений с прототипом, но не служит проверкой магазина на телефоне. Новые пользовательские тексты здесь не добавляются; действующие русские строки прототипа мигрируют в EN/RU в LOC-01/02.

Повторение из корня проекта (`godot` — установленный Godot 4.7.2):

```text
godot --headless --path . --script scripts/tools/validate_inventory_trade.gd
godot --headless --path . --script scripts/tools/validate_inventory_trade_edges.gd
```

Журналы запусков и авторство локальной модели хранятся в `.tools/trade-*.log` и `.tools/ollama-godot/runs/`, вне Git. При приёмке проверяются не только код выхода и маркеры, но и отсутствие `SCRIPT ERROR`/`ERROR` и завершение всех групп.
