29 сентября 2026. Основание: ITEM-DATA-02 в STATUS и разрешение независимой работы при ожидающем PR. База dev `090139b`, ветка `codex/item-data-runtime`, отдельный локальный worktree. Городские файлы PR146 остаются у Claude; границы переданы через мост082. Ожидание ремонта пересечения казармы с частоколом не закрывается этой задачей.

Результат для игрока: существующие вещи, покупки, экипировка и старые сохранения работают с прежними свойствами; определения каталога хранятся как ItemData, а изменяемые экземпляры создаются отдельно и не портят исходные ресурсы.

Исполнитель Codex по D-047: связаны создание экземпляров, торговые транзакции, владение и валидация сохранений. Тестовые фикстуры тоже используют каталог, включая намеренную подмену определения. Это изменение контракта нескольких систем, а не механическая замена строк. Основные тесты и отдельный проход QA — Codex; внешним ревью это не называется.

## Границы и настоящий контракт

- `scripts/systems/inventory_system.gd`: `item_database` становится `Dictionary[String, ItemData]`; `_init_item_database()` копирует ресурсы отдельно для каждого Inventory. Второго словарного каталога нет. `add_item`, `buy_item`, `describe_item_id`, `can_equip_in_slot`, `_validate_save_item` читают типизированные определения.
- `ItemData.to_dict() -> Dictionary` остаётся границей создания независимой записи экземпляра/передачи прежнему ItemRules. Состав обязательных и отсутствующих необязательных полей не меняется; `stats`, `effect`, `tags` копируются. ID экземпляра и quantity назначает только Inventory.
- Публичные `items`, `equipped`, сигналы, ItemRules и формат сохранения остаются словарями. Тестовая подмена каталога выполняется отдельным ItemData, а не Dictionary; все прежние ожидания транзакций, категорий и отказов сохраняются.
- Разрешены InventorySystem, `scripts/items/item_data.gd`, `scripts/items/item_catalog.gd` (при необходимости), существующие `scripts/tools/validate_*`, использующие `item_database`, новый `validate_item_definitions.gd`, эта карточка и STATUS. Ассеты, `.tres`, локализация, UI, мир/город, версии APK и чужой checkout не меняются.
- Не входят общий разнос InventorySystem по файлам, новый баланс/торговец/сундук, новые слоты, миграция формата сохранения, сюжет и новая планировка. EN/RU и оформление прежние, нового пользовательского текста нет.

## Проверка до готовности

1. Исходные проверки каталога, торговли, транзакций, владения и сохранений; после изменения тот же набор и неизменные ожидания. Снимок десяти определений до ITEM-DATA-01 — независимая опора значений/отсутствия полей.
2. Два Inventory не разделяют изменяемые определения. Редактирование экземпляра/его вложенных полей не портит другой экземпляр, live-каталог и загруженный `.tres`; редактирование live-определения не меняет уже созданную вещь или ресурс на диске.
3. Неизвестный ID, нехватка мест/денег, полные стаки, повторные сигналы/реентерабельность, неверное сохранение и legacy-рюкзак: прежний отказ без частичной записи. Старое валидное сохранение проходит с теми же ID, quantity, ячейками и экипировкой.
4. Реальный мир/быстрые слоты и инвентарь на Windows, штатная сборка Windows/APK. Последовательные тесты с изолированным APPDATA; доказательства только `local/qa/item-data-02/`.
5. S23: до слияния проверить текущую общую APK без отката установленной версии, включая создание/перенос/экипировку/возврат после загрузки. Телефон у владельца; Codex без нового разрешения не устанавливает и не нажимает. До фактической мобильной проверки PR остаётся draft, Windows за неё не выдаётся.

Личная художественная оценка не требуется: внешний вид/текст/баланс не меняются. Принятие сюжетных PR не является зависимостью.

## Фактический результат

Реализация закончена; до мобильной проверки PR остаётся draft. Изменены определение каталога и граница создания экземпляра; старые тестовые ожидания сохранены, фикстуры приведены к ItemData. Отдельный проход diff/QA выполнен Codex.

- Windows/Godot 4.7.2, отдельный APPDATA: 15 наборов прошли без ошибок движка/скрипта. Включают каталог 54/54, новую изоляцию/старые сохранения 24/24, инвентарь без рюкзака 173/173, торговлю (в том числе 600 обменов), владение, транзакции, события, снимки, хранилище, действия и быстрые слоты мира.
- Ещё два набора имеют прежние проблемы: `validate_inventory_snapshot_edges` достигает ограничения рекурсии на циклическом входе; `validate_inventory_transfer` не проходит три проверки русского текста. Оба результата воспроизведены с исходными InventorySystem и тестом из dev090139b в том же окружении. Они не исправлены этой задачей; весь набор зелёным не объявляется.
