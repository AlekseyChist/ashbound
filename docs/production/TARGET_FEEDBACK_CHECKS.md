# Проверка касаний и подсветки целей

Дата: 20 сентября 2026. Фича `codex/target-feedback` от `dev` (`ebeb078`). Реализация и исправления игровых файлов, сцен и проверочных сценариев выполнены локальной `qwen3.8-24k:latest` через Ollama. Codex проверил изменения, запустил проверки и сборки. Результат принят для локального слияния в `dev`; отправка этой фичи в GitHub не выполнялась, `main` остаётся `055b620`.

## Проверенное поведение

- Свободные касания и эмулированная мышь не вызывают удар. На ПК настоящая ЛКМ атакует при захваченном курсоре; кнопка «Удар» работает отдельно.
- По уточнению владельца явная команда атаки работает и без цели: герой может махать кулаками в воздухе.
- Доступное взаимодействие отмечается золотистым кольцом и лёгким осветлением NPC; доступное попадание по тренировочной мишени — красноватым кольцом. Подсказки называют действие и получателя.
- Дальность, препятствие, направление удара и повторный старт корректно меняют выделение; исходный цвет NPC восстанавливается.

## Сценарии Godot

Все шесть сценариев завершились с кодом 0 и своим маркером успеха:

| Сценарий в `scripts/tools/` | Что проверено | Маркер |
| --- | --- | --- |
| `validate_courtyard.gd` | Учебный маршрут, недопустимый порядок, дальность, направление, задержка атаки, сброс; одинаковое перемещение при разных частотах поз | `ASHBOUND_COURTYARD_OK` |
| `validate_camera_touch.gd` | Независимые пальцы движения, обзора и атаки; потеря фокуса и сброс | `ASHBOUND_CAMERA_TOUCH_OK` |
| `validate_courtyard_touch.gd` | Сенсорные кнопки и владение касаниями интерфейса | `ASHBOUND_COURTYARD_TOUCH_OK` |
| `validate_third_person.gd` | Камера за спиной, движение относительно камеры, поворот во время атаки, препятствие и наклон | `ASHBOUND_THIRD_PERSON_OK` |
| `validate_target_feedback.gd` | Выбор NPC, фактическое взаимодействие, смена цели, восстановление цвета, стены, направление атаки, свободный удар и сброс | `ASHBOUND_TARGET_FEEDBACK_OK` |
| `validate_target_input.gd` | Касания свободного экрана и обзор без удара, эмулированная мышь, настоящая ЛКМ, свободный курсор, кнопка атаки без цели | `ASHBOUND_TARGET_INPUT_OK` |

Последний сценарий запускался в настоящем окне Godot с OpenGL; остальные — без окна. Сенсорные события в сценариях синтетические. Это проверка обработчиков, а не завершённая приёмка физического ввода несколькими пальцами на телефоне.

Пример запуска из корня проекта:

```powershell
& '.tools/godot/Godot_v4.7.2-stable_win64_console.exe' --headless --path . --fixed-fps 60 --script scripts/tools/validate_target_feedback.gd --quit-after 2400
& '.tools/godot/Godot_v4.7.2-stable_win64_console.exe' --path . --windowed --rendering-method gl_compatibility --script scripts/tools/validate_target_input.gd --quit-after 1200 -- --no-mouse-capture
```

`validate_courtyard_touch.gd` запускать без `--fixed-fps`: он проверяет защитный интервал по реальному времени. Локальные журналы этой проверки находятся в `.tools/target-*-check.log` и в Git не включаются.

Обе сборки пересозданы и проверены запуском; приведённые хэши относятся только к исправленным пакетам.

## Границы результата

NPC пока доступны для разговора; здоровье и урон жителям не добавлены. Цели разговора и атаки независимы и могут выделяться одновременно с разными подсказками. Samsung S23, длительный нагрев, замеры стабильных FPS и полная физическая проверка нескольких пальцев остаются открытыми. Эта фича не закрывает всю Android-поддержку или этап M3.
