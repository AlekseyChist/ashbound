# D-047 — распределение игровой реализации по сложности

23 сентября 2026. Прямое решение владельца после CONS-02A: Qwen получает простые ограниченные изменения; Codex разрешены сложный ввод, связи нескольких систем и трудные исправления. Основные проверки на ПК и телефоне сохраняются. Эта документная задача уточняет процесс перед CONS-02B, не меняет порядок игровых этапов.

База: `618b6671604d3c68c2d39e911a47f070740cae92`, ветка `codex/implementation-roles`. Исполнитель — Codex, поскольку меняются правила/документы. Проверяемый результат: следующая карточка явно выбирает исполнителя по сложности, а устаревшее требование обязательного Qwen не блокирует разрешённую прямую работу Codex.

Разрешены AGENTS, MEMORY, README, GODOT_CONNECTION, docs/README, STATUS, ROADMAP, CONSOLIDATION_PLAN, TASK_TEMPLATE, эта карточка; абзацы о ролях в архитектуре LOCALIZATION/LIVING_WORLD и дизайне COMBAT_MASTERY/COMBAT_FRAME_DATA/CHARACTER_VARIANTS; tools/README и вводный комментарий моста Ollama. Локально синхронизируются только SKILL.md и references/ashbound.md навыка ollama-task-briefs с резервной копией. Исторические отчёты сохраняют фактическое авторство прежних реализаций.

Вне объёма: игровые скрипты/сцены/ассеты/баланс, APK/EXE, касания телефона, новая модель, смена провайдера или передача реализации облачным субагентам. Отдельное действующее правило Blender сохраняется. Интерфейсы игры, EN/RU и сохранения не затронуты.

Критерии: чёткие примеры простой и сложной задачи; выбор исполнителя и причина в карточке; явная передача трудного исправления Codex без повторного разрешения; сохранённые QA/Git/мобильные требования. Ошибки собственных тестов исправляет Codex; их не считать провалом Qwen. Лимит инструмента сам по себе не доказывает неспособность модели. При повторном неуспехе после одного обоснованного возврата — пересмотр причины и принятие сложной части Codex вместо цепочки мелких перепоручений.

Проверка Codex: содержание и согласованность актуальных правил, ссылки, уникальность D-047, diff только документов и комментария; контрольные суммы пользовательских файлов, текущих/прежних сборок и main. Новые игровые тесты и установка APK для этой документной задачи не нужны. Личная художественная приёмка не требуется. После проверки — PR в dev, точный head, GitHub-слияние и удаление ветки. Следующая игровая задача остаётся CONS-02B.
