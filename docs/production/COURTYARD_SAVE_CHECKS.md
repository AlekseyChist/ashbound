# SAVE-01A — проверки сохранения двора 0.11.0

21 сентября 2026. Ветка `codex/courtyard-save` от `dev` после PR #31. Игровые компоненты и интеграцию написала и исправляла локальная `qwen3.8-24k:latest`; Codex разработал, запустил и оценил основные тесты. [Схема и жизненный цикл](../architecture/COURTYARD_SAVING.md).

## Выполнено

Первый двор автоматически продолжает задание, инвентарь/экипировку/носимые хранилища, назначения, прогресс героя, положение/камеру и состояние листа карты. Начало новой установки остаётся пустым. Карта не выдаётся повторно при загрузке; прежние награды не проигрываются. Ошибки файлов показаны отдельными сообщениями EN/RU, без новых полос состояния героя.

Три компонента отделяют работу с файлом, проверку согласованности данных и связь со сценой. Два поколения одного профиля и проверка целостности позволяют восстановить предыдущую исправную запись; неисправные файлы при полном отказе сохраняются. Кнопка повторного упражнения не удаляет вещи и не выдаёт дубликаты карты. Полный SAVE-01 для всей будущей кампании этим не завершён.

## Независимая проверка Codex

- **25 основных наборов Godot PASS**; код выхода, обязательные завершающие маркеры и журналы проверены. Основная игровая регрессия 0.9.2 после принятия поручения сохранена.
- `validate_courtyard_save_store.gd`: **9 групп** — пустой старт, точный int64, два поколения, незавершённый временный файл, обрезанная запись, нарушенная контрольная сумма, неизвестная версия, семантически неверное новое поколение, отказ записи/переполнение, сохранность повреждённых файлов и отказ устаревшего процесса. Несколько условий объединены в группы.
- `validate_courtyard_save.gd`: **9 групп**, **30 неверных снимков** — реальная экипировка/размещение, завершённый и частичный урок, цельный перенос всех данных, отсутствие повторной выдачи очков, карта/источник/журнал, быстрые ссылки, согласованные уведомления и повторный вход, запись после серии событий, физическое открытие меню после загрузки, сброс упражнения, пауза, полный отказ загрузки. PASS без рендеринга и в графическом режиме; после уточнения защиты повторного входа целевой тест повторён.
- `tools/validate-courtyard-save-process.ps1`: записывающий процесс завершён принудительно после контрольной точки; отдельный новый процесс восстановил задание FETCH_WOOD, надетый рюкзак с хлебом, карту, деньги, быстрый слот, позицию/камеру и историю выдачи очков. Реальный жест открытия, просмотр задания и карты PASS.
- Два обычных запуска основной сцены без тестового скрипта: первый сообщил `empty`, следующий `loaded`. Существующий редактор не закрывался. Тестовые скрипты и сцены не обращаются к профилю владельца.
- **111 ключей EN/RU PASS**, проверены зависимости экспортированной APK и совпадение исходников со сборочными копиями. Windows EXE запущен и снял кадр без ошибок; итоговый сборщик сообщил `TRANSFER_FINAL_BUILD_PASS`.

В первых ответах Ollama обнаружены неверные API хэша/сигналов, ошибочные пути данных, пропущенная семантическая проверка файла и неправильная последовательность начальной записи. Они возвращены модели конкретными ограниченными заданиями и перепроверены; её сообщение об успехе не использовалось как приёмка. Проверка повреждённых данных не ослаблялась ради прохождения.

## Samsung S23

**SM-S911B, Android 16**, обычная и QA APK обновлены до **0.11.0-courtyard-save**, код **21**. Версии и SHA256 установленных APK совпали с собранными файлами. В обычной игре выполнено:

1. Пустой старт → подход к хозяйке → принятие дров → подход к ящику → получение схемы → открытие журнала без предварительного закрытия реплики.
2. Принудительное завершение приложения из открытого меню, новый процесс. Задание FETCH_WOOD осталось, герой вернулся к ящику, листа на ящике нет, доступно «Положить схему». Вещи открываются, в кармане одна схема. Журнал и карта доступны на RU/EN.
3. Возврат карты на ящик → повторное принудительное завершение → новый процесс. Карман пустой, вкладка карты отключена и касание её не открывает.
4. Повторное получение листа → Home/возврат → обычное открытие журнала. Первое касание сразу после команды возврата оказалось раньше готовности окна; после готовности открытие через жест прошло. Это не скрывалось повторным запуском приложения.

В журналах трёх процессов: `empty sequence=1`, затем `loaded sequence=8`, затем `loaded sequence=9`; ошибок Godot/скриптов нет. Снимки: [до закрытия](../art/reviews/courtyard-save-0.11.0/s23-before.png), [восстановленный мир](../art/reviews/courtyard-save-0.11.0/s23-restarted.png), [вещь после перезапуска](../art/reviews/courtyard-save-0.11.0/s23-items.png), [журнал EN](../art/reviews/courtyard-save-0.11.0/s23-en.png), [карта после перезапуска](../art/reviews/courtyard-save-0.11.0/s23-map.png), [возвращённая карта недоступна после загрузки](../art/reviews/courtyard-save-0.11.0/s23-returned.png), [итоговый журнал RU](../art/reviews/courtyard-save-0.11.0/s23-final.png).

После сценариев телефон был оставлен с принятым поручением, носимой картой и журналом RU. Перед публикацией Ollama убрала только лишние пустые строки в конце двух файлов; целевые тесты повторно PASS, сборки пересобраны и установлены, обычная сцена повторно открыта через GodotAppLauncher. Игровая логика не менялась. Автоматические касания прекращены. На ПК открыт отдельный обычный двор 0.11.0 с автозагрузкой; WASD/мышь, E — взаимодействие, I/Tab — меню после жеста, Esc — закрытие.

## Границы проверки

Сохранение экипировки и быстрых назначений проверено на ПК, в том числе через разные процессы; на S23 проверен описанный обычный маршрут, не весь набор экипировки и отказов диска. QA APK установлена, но её полный сценарий этой версии на устройстве не повторялся. OnePlus не подключён и для 0.11.0 не проверен. Личная приёмка владельцем новой функции и длительные замеры не получены.

Полное обесточивание накопителя не моделировалось: проверены прерывание процесса, обрезанный файл и отказ записи. Не обещается нулевая потеря последних движений между контрольными точками или одновременная игра из нескольких процессов. Безопасность полностью враждебного вручную перекодированного файла не является отдельным аудитом этого этапа. Облачной синхронизации, выбора нескольких профилей, меню удаления/новой игры, сохранений будущих NPC/ран/экономики пока нет. До 0.11.0 состояние двора не сохранялось в файл, поэтому прошлый сеанс 0.10.0 автоматически не переносится.
