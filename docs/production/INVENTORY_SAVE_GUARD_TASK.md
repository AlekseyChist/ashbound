# INVENTORY-SAVE-GUARD-01 — отказ от повреждённых данных до миграции

## Контракт

- Результат: загрузка некорректного инвентаря отклоняется без ошибки рекурсии движка, потери текущих вещей и событий восстановления.
- Основание: на dev090139b `validate_inventory_snapshot_edges` воспроизводит `Max recursion reached` в `_migrate_legacy_bags`, хотя печатает итог OK. Обнаружено при независимой проверке ITEM-DATA-02; исправление не зависит от PR152.
- База: `090139be4d8507ca9ed7a8ede1b57993dafb54b0`; ветка `codex/inventory-save-guard`.
- Исполнитель: Qwen/Ollama — локальная замена небезопасного копирования перед существующей миграцией, без новых систем. Codex — постановка, тесты, независимая проверка diff и Git. Если изменится объём или потребуется сложная переделка — явная передача Codex.
- Файлы: `scripts/systems/inventory_system.gd` (только начало `_migrate_legacy_bags`), `scripts/tools/validate_inventory_snapshot_edges.gd`, эта карточка и STATUS. Логи/задание/сборки — только local/.tools.
- Не входят: каталог PR152, баланс, формат schema1, UI/локализация, сохранения владельца, архитектура кампании, торговля и старая проблема RU-подписей transfer.

## Реальные интерфейсы

`load_save_data(data: Dictionary) -> bool` вызывает `_validate_save_data(source: Dictionary) -> Dictionary`, затем атомарно присваивает items/equipped/gold/layout и посылает события. `_validate_save_data` начинает с `_migrate_legacy_bags(source: Dictionary) -> Dictionary`. В ней `source.duplicate(true)` выполняется до валидации и падает на цикле.

`_deep_copy(value: Variant, depth: int = 0) -> Variant` уже ограничивает глубину32, отклоняет Object/Callable/RID и mutable-ключи; при отказе возвращает null. `_validate_save_item` вызывает её с глубиной0 относительно записи предмета. Сохранить этот предел для записей: предмет находится внутри корня → items/equipped → запись. Не уменьшать допустимую глубину старых обычных метаданных из-за двух контейнеров сверху.

## Приёмка Codex

1. Повтор исходного сбоя, фиксация ошибки движка отдельно от маркера OK.
2. Циклы Array/Dictionary в предмете, корне, storage и удаляемом legacy-поле отклоняются атомарно и без событий/ошибок; источник не мутирует.
3. Допустимые вложенные метаданные на прежней границе глубины загружаются и копируются независимо; более глубокие отклоняются.
4. snapshot, snapshot_edges, no_backpack (миграция), ownership/storage/transactions и сохранение мира — последовательно на Windows, отдельный APPDATA, без окна поверх игры владельца.
5. Экспорт/проверка текущей общей APK отдельно; старую маркировку dev0.36.4/code85 на телефон не устанавливать. До мобильной проверки результат — draft, без просьбы владельцу тестировать старый APK.
