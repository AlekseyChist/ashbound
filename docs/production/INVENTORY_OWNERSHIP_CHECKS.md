Игровой код написан установленной локальной `qwen3.8-24k:latest`; Codex задал контракт, прочитал изменения и лично запустил Godot. Первый регрессионный тест написала Ollama. ## Контракт

- `equip_item` и `use_item` принимают словарь с непустым строковым `instance_id`. Это ссылка на конкретную запись носимого инвентаря. Остальные поля переданного словаря не определяют тип, свойства, эффект, слот или требования вещи: система читает настоящую запись. Это позволяет будущему UI передавать копию/ссылку и не принимать её устаревшее содержимое за истину.
- Неизвестная, израсходованная, неоднозначная или отсутствующая ссылка отклоняется без изменений. Вещь, которая уже надета, нельзя повторно взять из сумки. Это контракт локальных операций, а не защита от прямого изменения публичного массива или проверка файла сохранения.
- При замене снаряжения старая вещь занимает место, освобождённое новой. Полная сумка сама по себе не мешает обмену. Сохраняются исходные словари и ID обеих вещей. Простое снятие при полной сумке отклоняется целиком.
- Проверки требований выполняются до изменения вещей. Сигналы экипировки видят уже завершённый обмен и пересчитанные характеристики. Пустой или неизвестный слот возвращает пустой словарь через `get_equipped`; попытка снять его возвращает `false`.
- Применение расходника списывает ровно одну единицу из выбранного экземпляра/стопки, сохраняя другие стопки того же типа. Списание происходит до вызова эффекта: обработчик лечения не может снова использовать последнюю уже потраченную вещь. `item_removed` сообщает об успешном применении после эффекта.

## Границы

Работа относится к общей логике Inventory. Первый двор пока использует собственное учебное состояние; меню, носимые ёмкости, карта и быстрые слоты появятся отдельными задачами. Уже открытый тест Godot и установленная на S23 версия 0.4.3 остаются доступны владельцу.

Числа лечения/выносливости в старой базе предметов не являются утверждённым балансом новой системы ран. WOUND-01/REST-01 отдельно должны запретить восстановление при необработанной травме и полное восстановление предметами. В этом проходе проверяется владение расходником, а не готовность лечения по новому дизайну.

Деньги, покупка/продажа, безопасная загрузка и полное сохранение остаются следующими задачами. В частности, `sell_item` пока не имеет этого контракта владения и не готов для подключения к пользовательскому интерфейсу торговли.

Операции требуют строковый ID и целочисленное количество в настоящей записи. Будущая проверяемая загрузка должна восстанавливать эти типы после JSON; произвольные словари через прежний `load_save_data` пока не считаются принятой системой сохранения. Первый двор не сохраняет Inventory, поэтому эта задача не мигрирует существующие игровые сохранения.

## Проверка

Первый сценарий `scripts/tools/validate_inventory_ownership.gd` содержит 12 случаев: отсутствующая вещь, изменённая копия настоящего экземпляра, обмен при полной сумке, требования фракции, снятие экипировки, расходование последнего предмета, выбор нужной стопки, отсутствие игрока и неподходящий тип.

- На исходном `dev` (`671b071`) — выход 1, **26 нарушенных проверок поведения**. Ошибки подготовки самого теста (слияние стопок в фикстуре и вызов функции сравнения ссылок) исправлены Ollama до этого контрольного запуска.
- После исправления — выход 0, `ASHBOUND_INVENTORY_OWNERSHIP_OK`. Между этим красным и зелёным запуском тест не менялся: SHA-256 `49D3E7C00B42C53CD18119E3466DD3A71137F6AFAD6E8981A5ECDF6B553A026D`.
- Первую реализацию отклонили: она неверно считала место при обмене. Затем Godot выявил ошибку вывода типа переменной. Обе исправлены локальной моделью; тест не ослаблялся. При чтении diff также убраны добавленные моделью вне задания ссылки на несуществующие иконки.
- Прежние `validate_inventory_transactions` и `validate_inventory_events` — выход 0 с обоими маркерами успеха: сохранены операции количества и их сигналы.
- `validate_courtyard` — выход 0, `ASHBOUND_COURTYARD_OK`: учебный маршрут, три попадания, повторный старт, одинаковое пройденное расстояние 3,793 м при 5 и 15 позах в секунду.

- Дополнительный `validate_inventory_ownership_edges` — выход 0, `ASHBOUND_INVENTORY_OWNERSHIP_EDGES_OK`, без ошибок движка. Пять групп: пустые слоты/замена брони/сигналы итоговых характеристик; эффект настоящего расходника и ограничение выносливости; попытка повторного применения внутри `heal`; отсутствующие возможности или уже удалённый игрок, неверное количество; неоднозначные и некорректные ID. Проверяются сами записи, события и состояние наблюдателя. Для эффекта используется тестовый Node3D, не готовая система ран.
- Черновик дополнительного теста был отклонён из-за неверных API, фикстур и ложноположительных проверок. Финальный тест считает завершённые группы: неожиданное прерывание функции не выдаёт успех. Codex также проверяет журнал на `SCRIPT ERROR`/`ERROR`, а не только код выхода и маркер.
- Импорт редактора — выход 0, без ошибок скриптов. При восстановлении прежней сцены `player.tscn` остаются известные предупреждения о старом UID FBX и объёмном тумане вне Forward+; эти файлы не изменялись.
- Документация, локальные ссылки и `git diff --check` проверены перед публикацией.

Все проверки выполнены на Windows в Godot 4.7.2 отдельными процессами. Новый APK в этом проходе не собирался и на телефоны не устанавливался: интерфейс двора не подключён к этим операциям. Ранее открытое ручное окно ПК и сборка S23 0.4.3 не являются доказательством проверки нового Inventory на Android. Несохранённый редактор владельца не закрывался.
