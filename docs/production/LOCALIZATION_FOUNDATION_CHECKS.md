# Основа EN/RU — LOC-01A

20 сентября 2026. Ветка `codex/localization-foundation` от `dev` (`2d1ac44`). Игровой модуль, PO/POT, регистрация и параметры экспорта написаны установленной локальной Ollama. Codex написал основные проверки и расширил разрешённые типы файлов её моста на PO/POT и конкретный `export_presets.cfg` с сохранением ограничения `--allow-file`.

## Что входит

Отдельный первый autoload `Localization`, настройки языка приложения, разрешение локали устройства, английский резерв, девять сообщений EN/RU, формы числа и однопроходная подстановка имён. Чтение не создаёт файл настроек; выбор сохраняет посторонние секции. Отказ записи не меняет активный язык. Полная документация API — [localization/README.md](../../localization/README.md).

Старые русские строки двора не мигрировали, переключатель языка ещё не встроен в HUD. INV-01, полный LOC-01/02 и литературная редактура сюжета этой задачей не закрываются. Кампанийные данные, управление и первая сцена не менялись. Использован встроенный шрифт Godot; отдельно шрифты не скачивались.

## Независимая проверка

`validate_localization.gd`: восемь завершённых групп — распознавание языка, первый запуск/неверная настройка, сохранение и события, отказы, тексты/параметры, множественное число, английский резерв, наличие символов и независимость инвентаря. Проверены русские формы 0/1/2/5/11/21/22/25/101/112, сохранение иных настроек, буквальное имя `{count}`, отказ записи в отсутствующий каталог. Файлы проверки создаются только под `.tools`, пользовательский `settings.cfg` не меняется.

Первый результат Ollama отклонён: Godot не загрузил PO из-за неиндексированной первой множественной формы, а распознаватель ошибочно считал `russian`/`rubbish` русскими локалями. Восемь групп завершились с 41 нарушенным утверждением. После исправления игровой реализации тем же тестом получено `ASHBOUND_LOCALIZATION_OK groups=8`, без ошибок. SHA-256 контрольного файла: `DA4D37DB92CC6806873EF04B62C7D9F438322157CA22004F1AE1FBEB2150729A`.

Два отдельных процесса `validate_localization_restart.gd -- write` и `-- read` подтвердили восстановление сохранённого русского выбора при английской локали устройства. Это разные процессы, а не изменение переменной одного экземпляра. `validate-localization-catalogs.mjs` проверяет девять одинаковых ключей, отсутствие дубликатов/fuzzy/пустых переводов, индексированные формы, параметры, UTF-8 и пустой POT. Встроенный шрифт имеет латиницу/кириллицу, `Ё/ё`, цифры и проверенные знаки; это проверка наличия глифов, не визуальная приёмка будущего меню.

Первичная проверка PCK из обоих пресетов обнаружила отсутствие PO: выбранный режим экспорта только сцен не включил их автоматически. Ollama добавила `localization/*.po` в `include_filter` обоих пресетов. Повторный экспорт Windows/Android прошёл; каждый PCK отдельно смонтирован в пустом QA-проекте, оба каталога и скомпилированный модуль загружены из пакета, одиночный текст и формы числа EN/RU прошли (`ASHBOUND_LOCALIZATION_PACK_OK locales=2`). Журналы `.tools/localization-export-*-final.log` и `.tools/localization-pack-*-final.log` не содержат ошибок. Это устранило реальный дефект упаковки, а не только проверило наличие исходных файлов.

Учебный маршрут двора и импорт редактором прошли. Старые предупреждения сцены о FBX UID/тумане остаются; новых ошибок скриптов нет. Логи `.tools/localization-*.log` и реальные ответы Ollama `.tools/ollama-godot/runs/` остаются локальными. Проверяется код выхода, обязательный маркер и отсутствие ошибок.

## Воспроизведение

```text
node tools/validate-localization-catalogs.mjs
godot --headless --path . --quit-after 120 --script scripts/tools/validate_localization.gd
godot --headless --path . --quit-after 120 --script scripts/tools/validate_localization_restart.gd -- write
godot --headless --path . --quit-after 120 --script scripts/tools/validate_localization_restart.gd -- read
```

Для упаковки использовать `--export-pack` с `Windows Courtyard` и `Android Courtyard`. `validate_localization_pack.gd` запускать по абсолютному пути из отдельного пустого QA-проекта, передав абсолютный путь PCK после `--`. Он монтирует пакет и загружает оба перевода и модуль без возможности подхватить пропущенные файлы из исходного проекта. Это проверка ресурсов Android-пресета на компьютере, не выполнение APK на Android.
