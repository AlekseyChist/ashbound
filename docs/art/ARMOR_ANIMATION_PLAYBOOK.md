# Герой и сеты брони: обязательный производственный рецепт 2.0

**D-079, 24 сентября:** рецепт применяется к единственному принятому главному герою. Новые сеты меняют одежду/оружие, сохраняя лицо, волосы, бороду и анатомию; головной убор может закрывать существующие части внутри рисунка сета. CHAR-01 и вариации внешности исключены. [Контракт](../design/LIFE_AND_ECONOMY.md).

23 сентября 2026. Основание — личная положительная оценка владельцем **AshBound Walk Preview 0.19.4/code49 на Samsung S23**. Это принятый образец движения без рюкзака. [Замороженная опора](../../art/characters/accepted-traveler-v1/README.md) и её manifest важнее старых проб. Для нового сета этот документ читать вместе с [CHARACTER_VARIANTS](CHARACTER_VARIANTS.md).

## 1. Что именно принято

Стойка и передний/задний шаг из текущей базы, новая боковая ходьба WALK-POSE-06, нарисованный боковой бег PAINTED-MOTION-04, передний/задний бег с согласованным масштабом MOTION-SCALE-05. На телефоне они объединены только в отдельном Walk Preview. Принятие этого набора не означает готовности всех атак, техник, оружия, новых сетов или переноса в кампанию.

Сохраняем не только понравившийся PNG: **рисунок + последовательность + длительности + сетка + опора + pixel_size + камера/свет** составляют результат. Ни один из этих компонентов нельзя менять незаметно при производстве брони.

Сначала проверить `python art/characters/accepted-traveler-v1/verify.py`. Изменившийся файл — причина остановить воспроизведение и выяснить отличие, а не переписать ожидаемый хеш. Проверка ничего не рисует и не исправляет.

Точное восстановление выполняется из сохранённых PNG и закреплённых сборщиков. Повторный запрос к генератору **не гарантирует тот же рисунок**, даже с прежним текстом. Текст запроса сохраняется как происхождение/пример; исходный RGBA — настоящий воспроизводимый материал. Принятые исходники не перезаписывать: новый сет/вариант получает новую папку и manifest.

Команды для текущей принятой базы из корня репозитория:

```text
python art/characters/accepted-traveler-v1/verify.py
python art/characters/walk-consistency-v1/build.py
python art/characters/painted-motion-v2/build.py
python art/characters/accepted-traveler-v1/verify.py
node tools/build-forest-route.mjs --walk-preview --baseline-root <основной-checkout>
```

Нужны Python/Pillow, Node и Godot из GODOT_CONNECTION. Сборщик бега исторически также восстанавливает старую walking-картинку в painted-motion-v2; **принятая ходьба берётся только из walk-consistency-v1**. Не подключать старый walk по похожему имени. Для чистого восстановления использовать отдельную ветку/worktree. Версии Python/Pillow при фиксации записаны в manifest; при несовпадении PNG сравнивать также декодированные пиксели, не объявлять другой файл исходным без проверки.

## 3. Упаковка и масштаб: не компенсировать дважды

В обоих боковых атласах 4 столбца × 2 строки, 8 ячеек **384×384**, без индивидуальной подгонки по bounding box. Каждый кадр — цельная фигура на прозрачном фоне; длительность 1, скорость клипа 15 поз/с. Физика/камера работают независимо от частоты поз.

Ходьба: ячейки исходного листа идут слева направо, верхний ряд затем нижний. Целая ячейка масштабируется ×0.75 и помещается со сдвигом **(0,56)**. Все восемь получают одинаковое преобразование; точные округления и alpha-проверки находятся в `walk-consistency-v1/build.py` и `packing.json`.

Бег: утверждённый порядок исходных ячеек **[0,1,6,7,4,5,2,3]**, а не порядок генератора. Исторический сборщик содержит фиксированную нормализацию, опоры/смещения целых рисунков и RUN_SCALE=0.53/0.9. Сохранять его фактический manifest; не придумывать новую нормализацию ног/головы. Не копировать этот коэффициент в ходьбу или новый сет автоматически.

| Метаданные принятого SpriteFrames | Значение |
| --- | --- |
| `pixel_size_side` | 0.00593080724876441 |
| `pixel_size_back` | 0.0059900166389351 |
| `pixel_size_front` | 0.00577849117174959 |
| `pixel_size_walk_side` | 0.005634266886326189 |
| `pixel_size_run_side` | 0.004803953871499164 |
| `pixel_size_run_front` | 0.005778491171749589 |
| `pixel_size_run_back` | 0.0059900166389351 |
| `baseline_offset_pixels` | 182 |

Это **конечные значения**, не дополнительные множители. Runtime выбирает `pixel_size_<action>_<view>`, затем fallback `pixel_size_<view>`; высота Sprite3D = baseline × pixel_size. При переносе из preview использовать готовые значения один раз. Одновременная компенсация в PNG, TRES и runtime меняет рост. Длинный меч, плащ, шлем или наплечник не являются основанием уменьшать героя по общему силуэту.

## 4. Порядок производства одного нового сета

1. **Карточка и опора.** Выбрать один сет и один первый клип — боковую ходьбу. Записать принятый commit, manifest, точные входные PNG, имя комплекта, покрытие тела, палитру/материалы и разрешённые файлы. Не начинать десятки действий одновременно.
2. **Образец комплекта.** Согласовать одну цельную позу нового сета рядом с тем же кадром принятого героя, в одном масштабе/свете. Броня вправе утолщать свой силуэт; череп, длина рук/ног, таз и точки опоры сохраняются. Внешность героя фиксирована D-079; изменение камеры обсуждать отдельно.
3. **Один согласованный лист.** Передавать генератору/художнику принятый целый лист движения и образец комплекта. Просить изменить одежду на всех фазах, сохраняя фазу, ракурс, лицо/волосы, пропорции, расположение корня и фон RGBA. Сохранить исходный ответ без перезаписи. Не собирать удачные головы из случайных генераций.
4. **Проверка до упаковки.** Сначала весь лист и шов последняя→первая. Голова/торс не меняют модель; ближняя и дальняя нога действительно меняются; руки идут противофазно; при шаге есть опора, колено проходит низко. При беге есть отличимые контакт/отрыв/полёт, не присед и не дрожание одной ведущей ноги. Текст задания не является доказательством правильных фаз — смотреть пиксели.
5. **Ограниченная доработка.** При дефекте назвать конкретные кадры/часть движения и сохранить уже согласованный верх/сет. Получить новый цельный лист/позы. Не лечить смену лица масштабированием кадра и не переходить к кукле из повёрнутых частей. Для нынешней ходьбы именно второй проход исправлял высокие колени и опору 8-го кадра.
6. **Упаковка.** Новая папка, фиксированные параметры для всего клипа, manifest с исходными SHA, фазами, atlas rect, общей опорой/масштабом, длительностями. Никакой покадровой автоподгонки роста. Если новый исходник имеет другую сетку, сначала привести целые ячейки к согласованному шаблону и проверить анатомическую опору; не подбирать отдельный zoom каждой фигуры.
7. **Сравнение.** Новый сет и обычный герой рядом, одна камера/дистанция/свет. Снять raw-позы, normal/slow loop и реальное движение. Только после бокового клипа расширять стойку, другие ракурсы и бег. Сохранять полный согласованный набор до подключения.
8. **Игровая проверка.** Смена action/view/set сохраняет опору и фазу; инвентарь/атака не повторяют события из-за переодевания. Установить актуальную отдельную APK на телефон, сверить version/code/base.apk SHA, открыть и передать владельцу. После передачи автоматические касания прекращаются. Художественная приёмка записывается отдельно.

## 5. Критерии брака и обязательные сравнения

Не принимать: прыгающие размер/наклон головы, разную длину торса, смену перспективы между шагом/бегом, постоянную ведущую ногу, высокий присед, скольжение опорной ноги, обрезанный клинок, ореол вместо прозрачности, переменный оттенок кожи/ткани, шов 8→1 с заметным скачком. Цифры помогают локализовать, но не заменяют просмотр.

Матрица: idle/walk/run × front/back/right/left, вход/выход действия и поворот на ходу; обычная и замедленная петля; малый мобильный размер и крупный head/torso strip. Одинаковые позы/масштаб проверяются в одной сцене, без зума камерой для сокрытия разницы. Наклон бега естественно уменьшает силуэт — выравнивать нужно анатомический размер и камеру, а не высоту каждого bounding box.

Симметричный безоружный бок разрешено зеркалить для другой стороны. Это **не** разрешение получать зеркалом вторую половину шага. С ножнами/щитом/оружием и асимметричной бронёй нужны отдельные стороны и сохранение ведущей руки. Две техники боя и художественный класс оружия — отдельные оси; не умножать автоматически всё на всё, производить только необходимые сочетания. Рюкзак и парные варианты запрещены D-057; цельный сет, кошелёк без визуального аксессуара.

## 6. Шаблон художественного поручения

```text
Задача: один цельный комплект <ID>, клип <действие/ракурс>.
Неизменяемая опора: <commit>, <manifest>, <полный принятый лист>.
Дизайн одежды: <одобренный целый образец>, <материалы/палитра>.
Сохранить: лицо/волосы, анатомию, камеру, фазу каждой ячейки,
направление взгляда, опору, общую сетку и прозрачность.
Изменить: только комплект в пределах согласованного дизайна.
Выход: полный RGBA-лист без текста/сетки/теней пола/эффектов;
8 целых поз, две разные половины шага, исходник не перезаписывать.
Проверка: соседние головы/торсы, контакт ног, шов, normal/slow,
переход idle→walk→run, один масштаб в Godot, свежая APK.
Запреты: отдельные runtime-накладки брони, рюкзак, морфинг,
разрезание героя на вращаемые конечности, случайные новые API.
```

Пакет выпуска: brief + входные/выходные PNG + SHA + сборщик/версия зависимостей + manifest фаз/масштаба + сравнение/запись движения + результаты ПК/телефона + отзыв владельца + PR в dev. Не удалять прежний принятый пакет при отклонении новой брони. Любое отклонение от этого рецепта записать в карточке до работы и показать сравнение.
